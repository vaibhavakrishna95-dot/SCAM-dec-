Project Dossier & Whitepaper

About SCAMSHIELD

An end-to-end Machine Learning and Cyber Threat Intelligence System designed to detect, dissect, and neutralize deceptive text communications.

Project Objective & Academic Scope

The proliferation of digital banking, e-commerce, and mobile messaging has produced a massive wave of social engineering fraud: from fraudulent lottery prize claims and urgent OTP harvesting to fake package tracking links.

SCAMSHIELD was built to provide a reliable, transparent, and multi-layered threat classification engine. Rather than operating as a black-box scoring algorithm, it pairs statistical natural language processing with explainable heuristic red flags and safe text-based URL parsing to empower users with actionable defense recommendations.

Machine Learning Workflow & Pipeline

[STAGE 1] DATASET INGESTION & PURIFICATION

Loaded 5,574 labeled messages from the official UCI Machine Learning Repository SMS Spam Collection. Cleaned missing values and removed 403 duplicate records to prevent data contamination, resulting in 5,171 pristine benchmark records (4,518 ham, 653 spam).

[STAGE 2] TEXT PREPROCESSING & TF-IDF VECTORIZATION

Messages undergo case-folding, regex URL/phone/money normalization, and punctuation filtering. Feature extraction is performed via TfidfVectorizer fitted strictly on the 80% training set (unigrams + bigrams, sublinear TF scaling, max 6,000 features).

[STAGE 3] MODEL COMPARISON & SELECTION

Trained and compared Multinomial Naive Bayes (Alpha=0.1) against Logistic Regression (C=5.0). MultinomialNB achieved the highest test F1-score (94.86%) and accuracy (98.74%), serving as the production classification engine.

[STAGE 4] DBSCAN EXPLORATORY CLUSTERING

Integrated TruncatedSVD dimensionality reduction coupled with DBSCAN (cosine distance metric) to uncover dense spam campaigns and detect isolated noise anomalies (outliers), providing visual exploratory insights into zero-day scam patterns.

System Limitations & Adversarial Evasion

  • Adversarial Character Substitution (Leetspeak): Scammers may intentionally insert typos, special symbols, or spaces (e.g. P@yP@l or b a n k) to evade keyword and n-gram detection.
  • Image-Based Spam: Attackers often distribute screenshots containing urgent demands instead of plain text. (ScamShield's roadmap includes OCR integration).
  • The "Normal Safe" Fallacy: As enforced in our core engine, a clean prediction from an ML model does not guarantee an unknown message is safe. Users must maintain basic verification hygiene.
